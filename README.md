API Трекера привычек

Зачем этот API

Этот API нужен, чтобы пользователь мог создавать привычки и управлять ими в одном месте.

Что входит в сдачу

- `api.yaml` — OpenAPI 3.0.3 спецификация.
- `service/` — каркас сервиса, сгенерированный из спецификации через OpenAPI Generator.

В спецификации есть разные HTTP-глаголы: `GET` списка, `GET` одного объекта, `POST`, `PATCH` и `DELETE`. Для операций описаны параметры, успешные ответы и ошибки. DTO для входа и выхода находятся в `components/schemas`; внутренние поля базы данных в наружные DTO не включаются.

Как делали

Я выполнял задание с AI-ассистентом ChatGPT 5.6 Luna.

1. Я выбрал предметную область трекера привычек.
2. Я описал ресурс `habits`, авторизацию через Bearer JWT и DTO в `api.yaml`.
3. Я проверил структуру спецификации и запустил кодогенерацию через Docker:

   ```bash
   docker run --rm -v "${PWD}:/local" openapitools/openapi-generator-cli generate -i /local/api.yaml -g python-flask -o /local/service
   ```

Итоговые промпты

1. «Спроектируй OpenAPI 3.0 API для трекера привычек: список, получение одной привычки, создание, частичное обновление и удаление. Добавь summary, параметры, успешные и ошибочные ответы, Bearer JWT и отдельные DTO в components без внутренних полей».

Что я поправил руками

После генерации я вручную проверил и поправил:

- разные HTTP-глаголы и обязательные `operationId`;
- причины ошибок `401`, `400` и `404`;
- `readOnly` для идентификатора и дат;
- отсутствие внутренних полей хранения в `HabitResponse`;
- русские описания и примеры в `api.yaml`;
- описание процесса, модели, промптов и ручных правок в README.
